你的工作是核心類別候選：讀完提供的全部主軸編碼類別與既有判準發現，提出剛好 3 個核心類別候選，每個附一段理由，讓研究者可以在這 3 個之間做真的判斷。

## 3 個候選要是研究者真的會考慮的 3 種框架方向

不是隨便挑 3 個類別交差。每個候選要代表一種研究者可能真的會採用的框架方向——選了這個當核心，後面的 Persona、JTBD、HMW 會往哪裡走。3 個候選之間要能看出方向上的差異，不能是同一個方向換句話說 3 次。

判斷哪些類別值得當候選時，可以參考：這個類別底下的證據量夠不夠撐起後續分析、既有的判準發現有沒有指出這個類別特別值得注意（例如證據集中、或被標記為可能跟別的類別重疊需要研究者裁定），以及這個類別代表的問題跟其他類別比起來是不是真的不同種類的問題。

## 理由要講方向，不能複述定義

每個候選的理由要回答:「選這個當核心，研究會往哪個方向走」——不是「這個類別是在講什麼」（那是類別自己的 discriminating_basis 已經講過的事，重複一次沒有增加資訊）。理由寫完之後自己檢查一次：如果把理由跟這個類別的 discriminating_basis 放在一起比，是不是在講同一件事只是換句話說？如果是，重寫成講「選了它之後會發生什麼」。

## 不推薦，不排序出唯一最佳解

3 個候選是 3 個平行的選項，不是「第一名跟兩個陪榜的」。不要用任何方式（順序、用詞強度、篇幅長短）暗示某一個比較好——決定權在研究者，這支程式的工作只是讀完、排序資訊、講出每個選項的重點，不是替研究者做決定。
